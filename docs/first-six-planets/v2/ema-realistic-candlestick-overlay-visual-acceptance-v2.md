## 一、最终必须呈现的图像

像常见交易终端的BTC/USDT蜡烛图：**每根K线有真实可辨的实体和上下影线，红绿交替，包含推动上涨、回调下跌、震荡整理、假突破和反转**；在**同一个价格主图、同一时间轴和同一Y轴**叠加两条从历史收盘价计算出来的EMA：
- EMA20：金黄色**连续实线**，紧随价格波动而平滑弯曲；
- EMA50：浅蓝色**虚线**，反应较慢、通常更平滑；
- 两条均线穿插在蜡烛图实体和影线之间，随着市场走势上下起伏，不是与K线分开的示意曲线，更不是固定斜率直线。
- 成交量放在**下方独立区域**，不挤占K线主图；量柱高度不循环重复，允许量价不一致。
- 图上清晰可见价格刻度、时间刻度、EMA20/EMA50图例、十字光标OHLC及对应EMA数值。

**严禁：** 70根全绿匀速上涨、固定每根加同样价格、每隔N根循环同一组成交量、只有图例没有EMA曲线、将EMA画在副图、为了制造交叉而手绘与计算结果不符的线、用静态图片冒充可交互K线。

## 二、数据必须先于均线，均线必须从数据计算

先制作经过人工审阅的、有明显高低点与不规则回撤的版本化BTC仿真OHLCV数据，建议每场景至少160根（含预热）；然后按固定公式计算EMA20和EMA50，最后用相同时间/价格映射渲染K线和EMA。不得先画两条好看的EMA再倒推K线。

画面必须能让初学者**肉眼看见以下五种关系**：
1. 上涨趋势中K线围绕EMA20波动，EMA20通常在EMA50上方，但不是每根K线都在EMA20上方；
2. 至少两次回调，K线实体或影线靠近/穿过EMA20，随后有一次反弹、一次继续下探；
3. 横盘震荡时价格反复上下穿越EMA20，两条均线趋平并可能反复交叉；
4. 下跌趋势中EMA20/50逐渐向下弯曲，短暂反弹可以穿过EMA20又跌回；
5. 反转时先有价格结构变化，EMA20较快转向，EMA50较慢，展示指标滞后。

这些可以分为不同场景，不要求一张图挤满五种行情；每个场景的视觉必须清晰可辨。场景A上升回踩、B下跌反弹、C横盘假交叉、D反转滞后，分别由其OHLCV和指标计算结果支持。

## 三、可见性与比例

- 默认显示**双线**，黄线和蓝虚线至少各有连续40个有效可见数据点；若可见窗口不足，应调整初始视窗，而不是隐藏线。
- 主图占图表可用高度约70–80%，成交量占20–30%；EMA和K线使用相同价格轴；Y轴范围由当前可见K线高低价及有效EMA值计算并留5–10%余量。
- K线宽度、影线粗细、EMA线宽应在360/390/768/1440px均清晰；移动端初始可见约35–60根K线，桌面约60–100根，可缩放查看更多；禁止把160根全塞进手机导致每根变成一根像素线。
- 当EMA与实体重叠，使用高对比色、约2.5px线宽及清晰绘制层级，确保线能被跟踪；鼠标/手指选中K线时高亮两条EMA对应值。
- 如果截图中的EMA缺失，先检查有效值数量、可见窗口、坐标、裁剪、层级、按钮状态；必须找出实际根因，不能靠改图例假装修复。

## 四、必须亲手操作的教学流程

**第一步：隐藏EMA**，让用户先找出一段BTC上涨、两次回调和一段横盘；**第二步：显示EMA20**，观察K线何时接近/穿过黄线；**第三步：加入EMA50**，比较快慢线弯曲与价格变化；**第四步：逐根播放**，看价格反转时均线为什么滞后；**第五步：隐藏答案**，让用户在新场景自己圈出回踩、交叉和假信号。每一步必须在同一张可操作K线图上完成。

## 五、验收：不是“有线”就算过关

1. 提供**默认双线的真实运行截图**，能直接看见黄EMA20、蓝EMA50与红绿交替的蜡烛图同轴穿插。
2. 提供上涨回踩、下跌反弹、震荡假交叉、反转滞后**四个不同场景的运行截图和场景数据**，不能用同一条线改标题。
3. 提供至少一张**EMA20被K线实体穿越**和一张**EMA20/50真实交叉**的放大截图，并核对该交点与数值符号变化相符。
4. 提供手机390px和桌面1440px的真实截图；图中蜡烛实体、影线、两条EMA、价格刻度都清楚。
5. 核对每一根EMA值由该场景OHLCV的收盘价计算，主图十字光标读数与数据一致；测试改变周期后曲线确实变化。
6. 教学必须出现成功和失败的回踩/交叉例子，不能全是单边上涨；未来K线不得提前泄漏。
7. 交付实际代码差异、单测、场景JSON与可运行预览；缺任一项不得宣布“修复完成”。
