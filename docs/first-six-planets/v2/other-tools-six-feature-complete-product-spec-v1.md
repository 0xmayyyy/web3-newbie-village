## 2. 交易模拟舱｜核心项目P0
### 2.1 页面只分三块
**上：实时行情K线**（BTC/USDT、ETH/USDT起步，必要时扩展；价格、时间、数据源、实时/断线状态）；**中：买入/卖出操作**（现货、市价/限价、数量或金额、预计手续费、预计到账、确认）；**下：我的虚拟资产**（可用USDT、冻结USDT、币种余额、冻结币、持仓成本、浮动盈亏、未成交订单、成交记录）。桌面可把下单面板放图右边，手机纵向排列。绝不把交易终端几十个专业开关照搬给新手。

### 2.2 账户规则
- 初始资产：**1000.00虚拟USDT，BTC/ETH=0**；页面写清「不是真钱，不能提取」。
- 同一用户/浏览器首次进入只初始化一次；刷新、关闭重开不重新赠送。支持「重置练习」二次确认；重置前显示本轮盈亏摘要，可保留本地历史记录，允许清空。
- 余额分**可用**与**订单冻结**；买入限价单冻结所需USDT（包含预计最大手续费缓冲），卖出限价单冻结对应币量；撤单释放冻结。任何余额不允许小于0，任何币量不允许凭空增加。
- 持仓成本使用**加权平均成本**，含买入手续费的处理必须固定并解释；卖出实现盈亏和未实现盈亏分开，卖出后剩余持仓平均成本按该方法保持一致。资产总值=可用USDT+冻结USDT+各币种总持仓按最新**有效**市场价估值，避免双计冻结币。行情失效时停止实时估值并标「最后有效估值，非当前价格」。
- 数量与USDT金额输入互相换算；显示最小交易数量/金额、数量精度和价格精度的**模拟规则**，不要冒充交易所实际下单限制。

### 2.3 行情接入
- 使用合法可用的公开市场行情接口，优先支持WebSocket实时ticker及K线订阅；需核对数据供应商的访问限制、地区可用性、重连策略、频率限制和使用条款；**不能仅凭品牌名假设接口一定可用**。
- 首次加载REST历史K线，再用WebSocket更新当前未收盘K线；按交易所事件时间与K线起止时间去重合并；历史已收盘K线不得被错误覆盖。时区标注UTC/本地。
- 实时价格、K线、模拟撮合尽量采用**同一交易对与同一市场源**，避免图上价格与成交价格冲突；若用成交价/买一卖一需明确。
- WebSocket断线、报价超过阈值（建议5秒可配置）、数据源限流、切换标签页后重连：显示异常，**暂停新的模拟成交和触发条件判断**，不可继续用旧价执行。恢复后先校验连续性/补齐缺失数据，再恢复；若无法补齐，明确展示不确定性。
- 市场数据不是订单簿全量深度。若无深度数据，不能声称模拟了真实流动性或保证限价成交；使用透明的教学撮合规则。

### 2.4 模拟订单引擎（必须有确定性规则）
- **市价买单**：有效行情下，以明确报价基准（例如当前卖一；若无盘口则最新价+预设教学价差）加模拟滑点计算成交；检查可用余额包含手续费后原子扣款，记账、生成唯一成交ID。市价卖单使用买一或最新价减教学价差。手续费示例0.1%（**教学参数，不宣称等于交易所实时费率**）；用户可查看费率说明。
- **限价买单**：订单提交时冻结预算；当有效市场卖价<=限价时符合触发条件；**教学模式可按限价或更优价成交，规则必须固定显示**。限价卖单当有效市场买价>=限价触发。不能只因某根K线High/Low穿过价格就声称一定成交；若使用K线穿越近似，须明确「模拟触发，不代表真实订单排队成交」。
- **未成交订单**：状态OPEN、PARTIALLY_FILLED（仅在确实实现部分成交时启用）、FILLED、CANCELED、REJECTED；第一版可以**不做部分成交**，则不要展示该状态或伪造部分成交。
- **止盈止损**：第一版可在完成市价/限价核心后加入简单条件单。触发价与执行价分开；触发后按当时有效市场价模拟市价成交，**不保证按触发价成交**；行情断线不触发，恢复后按明确策略检查并提示可能跳空。
- **重复点击/网络重复事件**：下单请求有客户端唯一幂等ID；本地状态更新原子化，避免双扣；刷新后OPEN订单能恢复并继续监测，前提是行情恢复且规则明确。
- **费用/滑点**：下单确认页预览总花费、费用、预计成交币量；成交后以真实模拟成交价格和实际模拟费用记账，保留完整交易流水。买入和卖出手续费的计价币种需统一定义。
- **不允许**合约、杠杆、借贷、充值真实币、绑定交易所API密钥、真实钱包连接或真实下单。

### 2.5 练习任务（不额外增加复杂模式栏）
初始提示「用100虚拟USDT买一次BTC」→成交后解释持仓和手续费；接着「挂一笔不会立即成交的限价单」→「撤单看冻结余额恢复」→「卖出部分持仓看已实现盈亏」。任务作为图下轻量引导，不挡住交易界面。保留自由练习入口。

### 2.6 测试及拒收
- 首次1000，刷新仍1000；重复下单不双扣；余额不足拒单；限价冻结、撤单解冻、成交记账守恒；买卖费、盈亏可由独立手算核对。
- 行情断线后不能下单成交；重连能补齐K线；价格/订单事件去重；浏览器重启后订单和资产一致；重置有二次确认。
- 手机360/390px图、下单、余额不遮挡；成交/挂单/失败状态易懂。
- **拒收**：实时行情却虚构报价；只有买卖按钮无订单状态；余额刷新重置；限价单无冻结；以实时价展示假实时K线；使用真实资金。

## 3. 币圈模拟人生｜核心项目P0
### 3.1 游戏形态
单一故事地图，7个连贯章节，每章「情境描述→2至3个清楚选择→立即展示后果→一句解释→继续」。避免满屏卡片和冗长剧情。人物、交易所和地址全部虚构；不暗示任何真实平台保证安全。允许重试，不因错误强制从头。

### 3.2 七关与可验证分支
1. **第一次接触币圈**：有人发注册链接/假客服私信。选官方入口或陌生链接；错误触发「风险提醒」，不收集真实账号。
2. **账户安全**：密码重复使用、MFA、假验证码索取。错误展示可能的账号接管风险；正确开启虚拟安全标记。
3. **法币入金**：比较报价与费用，识别第三方收款/假转账截图；用**游戏专用虚拟法币余额**计算实际可得USDT，避免把实时汇率误当可执行P2P报价。
4. **第一次现货买入**：调用交易模拟舱的**任务入口**完成一次虚拟BTC买单；返回关卡时验证交易流水存在，不是点「已完成」就通关。
5. **第一次提币**：模拟选择BTC/USDT网络、核对收款地址、测试转账；错误网络和错误地址造成虚拟损失或暂停提示；区分链上不可逆与某些交易所内部可协助处理的情况。
6. **第一次用钱包**：连接、消息签名、授权额度、转账弹窗；识别恶意无限授权和签名内容不明，允许拒绝。
7. **毕业挑战**：混合情景：有人声称资产被冻结要求先付解冻费、假空投授权、转账网络不一致、报价过高；必须解释选择原因。

### 3.3 状态与经济模型
- **游戏故事资金与交易模拟舱的1000 USDT默认分账**，防止剧情失败导致自由交易账户无钱可练。第4关可使用独立「任务沙盒」账户或显式的可恢复快照；如要共用余额，必须在UI说明并经站长批准。
- 游戏记录：chapterId、choices、safetyFlags、taskReceipts、mistakes、virtualLoss、retryCount；每个分支的资产变化有明确账本，不允许扣款后刷新恢复成错误余额。
- 结局不是“发财/破产”预测，而是风险习惯报告：操作正确、危险授权、网络核对、报价理解、待复习课程；错题可回看，所有情节可重玩。
- 不新增独立全站学习进度系统；仅游戏内关卡进度。

### 3.4 验收
至少每关一条安全路径、一条常见错误路径及后果；第4关必须验证真实模拟交易记录；错选可重试；刷新状态稳定；不采集真实助记词、手机号、身份证、交易所账号。

## 4. 法币兑换与买币成本计算器｜P1
### 4.1 交互
顶部选择「从MYR/USD/CNY/SGD/JPY/HKD→USD或另一法币」，输入金额，显示**参考汇率、数据源、更新时刻与结果**。下方可选「估算购买USDT」，展示USDT参考买入报价、价差/手续费、最终预计获得USDT。默认MYR→USD→USDT，但支持切换。计算器无需真实交易或付款。

### 4.2 计算与数据
- FX: `targetAmount=sourceAmount*FX(source,target)`，需明确汇率方向；跨汇率以统一基准转换，避免将USD/MYR乘除颠倒。
- 外汇接口需确认许可、缓存策略、更新频率、地区访问、限流与失败降级；**如果提供商并非逐秒更新，不得标「秒级实时」**，应显示「最新可用参考汇率，截至…」。
- USDT与USD不严格等价。USDT估算必须使用独立报价 `USDT_per_USD` 或 `USD_per_USDT` 并明示方向；若没有可信USDT报价，则只显示美元参考金额并提示不能精确估算USDT。
- 费用：固定费用与比例费用分开，`netFiat=max(0,grossFiat-fixedFee-grossFiat*percentFee)`（若费用以其他币种收取需先转换），`USDT=netFiat/pricePerUSDT`；如有点差，在报价中体现且不重复扣除。手续费超过金额时结果为0并报错。
- 交易所P2P/银行卡实际到手报价可能与FX中间价不同；不宣传本计算器是可成交报价。
- 数据过期/离线：保留最后汇率并明显标注「过期，仅供参考」，不显示假实时。输入0、负数、NaN、超大值、货币相同、换向、极端小数都需正确处理。

### 4.3 验收
MYR→USD→MYR在不含费用的同一时点误差只来自四舍五入；USD/JPY方向正确；USDT报价偏离1时结果随之变化；费用显示明细；汇率更新时间和来源可见；离线不伪称实时。

## 5. 模拟转账｜P1
**一个画面：** 发送币种与数量→选择发送网络→粘贴/选择**虚构**收款地址→必要时填写Memo/Tag→核对费用→「模拟发送」。内置三个示例：正确TRC20转账、网络不一致、需要Memo但遗漏；另含地址被替换、余额不足、Gas不足、小额测试与重复提交。

- 使用教学网络/地址格式校验，不宣称「地址格式正确=收款方支持该网络」。链与币种、接收平台、地址类型三者必须同时匹配。
- 显示模拟手续费与到账数量；如果网络费由原生币支付，明确从对应虚拟余额扣费，不把所有网络费都当USDT扣。
- 模拟交易状态「待确认→已完成/失败/无法自动找回」，**不生成真实TxID或伪装真实区块浏览器链接**；虚拟TxID标「教学编号」。
- 用户错误选择时先展示「如果是真实转账，可能无法找回」并允许撤回到确认步骤；毕业关卡可模拟不可逆后果，但不诱导真实损失。
- 允许一键填入安全示例，不要求用户输入真实收款地址、私钥或助记词。
- 验收：网络不一致拦截或明确后果、Memo遗漏提醒、手续费资产正确、虚拟账本守恒、重复点击不双扣、成功/失败状态清晰。

## 6. 钱包签名模拟器｜P1
**一张仿真钱包弹窗**，上方标「虚拟钱包，不连接真实钱包」。提供四种逐步出现的请求：
1. **连接钱包**：显示拟共享的地址/网络，解释连接本身通常不直接转账，但网站仍可能读取公开信息并后续请求签名。
2. **普通登录签名**：展示域名、nonce、有效期、签名消息；说明签名不等于链上转账，但**恶意签名也可能有风险**，尤其结构化签名、Permit等，不能一概称「签名安全」。
3. **ERC-20授权**：展示合约/花费方、代币、额度（例如100 USDT与无限额度对比）、链与潜在后果；解释授权是允许合约在限额内转移资产，批准后还可能需链上撤销且需Gas。
4. **发送交易**：显示to、value、token、network、预计gas、可能的合约调用；不认识合约/内容不明应拒绝并核验。

**防骗情境**：伪装空投的无限授权、伪造域名、请求助记词、签名内容模糊。用户选择确认/拒绝→模拟后果及解释；不能把所有签名统称无害，也不能把所有授权统称立即被盗。

不加载钱包扩展、不请求真实连接、不存储真实签名、不让用户输入私钥或助记词。验收：四种请求差异明确、额度变化能改变虚拟风险后果、拒绝不会扣资产、撤销权限的模拟流程可见、恶意Permit示例能被正确解释。

## 7. 代币经济学模拟器｜P2
**一个图表 + 三个滑块**：代币价格P、流通量C、总供应量S（要求0<=C<=S）。实时显示：
- 流通市值 `MarketCap=P*C`
- 完全稀释估值 `FDV=P*S`
- 流通比例 `C/S`（S=0时不可计算）
- 新解锁数量U使新流通量`C'=min(S,C+U)`，在**假设价格不变**时新市值`P*C'`；FDV保持`P*S`。
- **示例**：价格1美元，流通1亿枚，总供应10亿枚→市值1亿美元、FDV10亿美元；解锁1亿枚且价格假设不变→流通2亿枚、市值2亿美元、FDV仍10亿美元。**不代表有1亿美元新资金流入，也不表示价格必然腰斩。**

第二层可选「如果价格跌10%/涨10%」的情景滑块，让用户看到价格变化和供应量变化的组合；不得用固定公式声称解锁必然导致某个跌幅。解锁日历若要接真实项目数据必须单独做来源校验，第一版只使用虚构示例。

练习：给两个项目同样市值但FDV不同，让用户判断稀释风险；给解锁后价格不变/下跌两种情景，区分数学恒等式与市场预测。验收：公式、单位、数值格式、边界0与极大数正确，滑块不会产生C>S，文案不把FDV当真实筹资金额。
