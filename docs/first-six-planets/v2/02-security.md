## 所有课通用版式（优先复用现有组件）
- 桌面：正文最大宽度约720px；整体内容区最大宽度1120px。标题28–32px、正文16–17px、行高1.7–1.85；正文段落间距12–16px；卡片内边距20–24px。移动360px：左右边距16px、标题22–24px、正文15–16px、行高1.7–1.8；卡片内边距16px。以上为设计建议，先和现有设计令牌比对，不硬改全站样式。
- **每屏只讲一个问题**：标题≤14个汉字、引言1–2行、正文每段2–4行、强调字最多1处；每屏正文建议80–180字，复杂操作拆屏，不强制每节六屏。图表旁最多3条短注释，完整说明放可展开“为什么”。
- 视觉节奏：正文→示意图→简短解释→操作→误区→轻量自测；避免连续三张同样的卡片、整屏大段文字、每行都加粗。宇宙紫蓝配色沿用现站；背景装饰透明度低，教学图用高对比度实线、标签不压线。
- 互动必须有**初始/输入中/错误/成功/重置**状态；按钮44px触控区；图表有数据表和文字说明；不用颜色作为唯一正确/错误信号；无动画偏好时关闭位移动画。
- 中文正文是供站长审核的**建议改稿**，开发前逐节对照原文，核对不删关键知识点；此文件不授权替换。数据全部教学虚构，涉及平台规则必须注明可能因地区/时间不同。

## 私钥、助记词、密码

### 中文建议文案（供站长逐节审核）
钱包密码通常是用来解锁你这台设备上的钱包界面；私钥用于控制对应地址的资产；助记词常用于恢复一组钱包密钥。三者不是一回事。有人索要助记词，无论说是客服、空投还是验证账户，都不要提供。

### 排版分屏
- **屏1 场景**：取文案第一句作引入；不超过两行，避免大字占满首屏。
- **屏2 解释**：将文案核心定义拆为1–2段，每段2–4行，关键名词只加粗一次。
- **屏3 图解**：设备密码→本地解锁；助记词→密钥恢复→地址控制；用不同箭头并注明具体钱包恢复方案可能不同。
- **屏4 动手**：给出‘客服要助记词/本地输入解锁密码/官网要求验证码’分类，逐条解释；禁止收集真实助记词。
- **屏5 易错点**：将文案末尾风险或限制单独放浅描边卡，最多两句；不要再重复正文。
- **屏6 自测**：问“本课哪种理解更准确？”，提供三个有辨识度的选项，正确项对应本节定义，错误项对应常见误区；正式题库在对照原课程后补齐，不得编程布自行猜答案。

### 交互规格
给出‘客服要助记词/本地输入解锁密码/官网要求验证码’分类，逐条解释；禁止收集真实助记词。。所有选项提交前不揭晓；提交后逐项说明依据；重置清空选择与反馈；小屏纵向排列选项，禁用横向溢出。图表/示意需提供屏幕阅读器文本替代。

## 连接、签名、授权、转账

连接钱包通常让网站知道你的地址；签名是在确认一段消息或交易意图；授权可能允许合约动用一定额度的代币；转账则是把资产发送出去。不同操作风险不一样，尤其要看签名具体内容和授权对象。
